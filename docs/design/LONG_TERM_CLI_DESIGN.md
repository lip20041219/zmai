## 1. 一年 3000 次的真相

### 1.1 使用分布

假设一年 3000 次打开 ZMAI：

```
约 300 次     ≈ 第一次使用 / 换项目 / 换机器         ← 这些是新用户时刻
约 2700 次    ≈ 日常使用：进入项目 → 说任务 → 得到结果  ← 这是老用户时刻
```

**2700 次是重复的。** 每一次重复，小的摩擦都会被放大 2700 倍。

### 1.2 什么是「舒服」的 CLI

一年后仍然舒服的 CLI = **不需要思考就能用的 CLI**。

判断标准很简单：

```
第 1 次使用：需要 3 秒思考 "怎么用来着？"    ← 正常
第 100 次使用：需要 0.3 秒思考               ← 还可以更好
第 1000 次使用：不需要思考，肌肉记忆           ← ✅ 这就是目标
第 3000 次使用：闭着眼睛都能用               ← ✅ 最终目标
```

### 1.3 什么会让人烦

```
第 1 次看到 "欢迎使用 ZMAI"    → 挺友好的
第 300 次看到 "欢迎使用 ZMAI"   → 能不能跳过？
第 1000 次看到 "欢迎使用 ZMAI"  → 不想再看到了

第 1 次等待 500ms 启动         → 能接受
第 1000 次等待 500ms 启动      → 太慢了
第 3000 次等待 500ms 启动      → 每天都在浪费 5 秒

第 1 次输入 zmai --backend deepseek    → 还能接受
第 300 次输入 zmai --backend deepseek   → 为什么不记住？
第 1000 次输入 zmai --backend deepseek  → 这个设计有问题
```

**一年后的用户不在乎功能多不多。他们在乎的是：**

1. **快不快** — 每次等待都在消耗耐心
2. **稳不稳** — 每次意外都在消耗信任
3. **累不累** — 每次多余操作都在消耗精力

## 2. 摩擦清单

### 2.1 启动摩擦

```
每次启动看到的：
┌────────────────────────────────────────────┐
│  ⚡ ZMAI v0.1.0                             │
│  模型无关 Agent Runtime                     │
│  项目: my-project · Python 3.13             │
│  Backend: DeepSeek (来自缓存)               │
│  Memory: 恢复上次会话                        │
│  Agent: swe (6 tools)                       │
└────────────────────────────────────────────┘
```

第 1 次：好看。
第 100 次：一行都不想看。
第 1000 次：**这些信息我能不能关掉？**

**问题：每次启动都有噪音。** 老用户知道自己在哪个项目、用什么 Backend。不需要提示。

**解决方案：** 默认安静。所有信息移到 `zmai status` 中。启动只输出一行：

```
zmai> _
```

如果启动出问题了，才输出信息。**无消息 = 正常工作。**

### 2.2 命令摩擦

```
zmai -p "task" --json         ← 每次都要输入 -p
zmai -r                       ← 恢复任务
zmai -r "continue fixing"     ← 恢复并继续
```

问题：
- `-p` 参数每天输入 10 次，一年输入 3000 次
- 双手离开主键盘区域去按 `-` `p` 键，每次 0.3 秒
- 一年浪费 15 分钟在按 `-p` 上

**解决方案：** headless 模式也接受位置参数。`-p` 保留但不需要天天用。

```
zmai "task"                   ← 不需要 -p，位置参数优先
zmai "task" --json            ← 加 --json
```

### 2.3 恢复摩擦

```
zmai status                   ← 先看有什么任务
  → 显示列表
zmai -r                       ← 恢复最近的
```

两次命令才能恢复。一天 2 次，一年 600 次额外命令。

**解决方案：** 一个动作完成。

```
zmai                          ← 自动恢复最近的未完成任务，没有就进入交互
zmai -r                       ← 有多个未完成时，显示列表选择
```

### 2.4 等待摩擦

每次启动等待项目检测、Backend 加载、工具注册。

```
第 1 次：500ms → 能接受
第 100 次：500ms → 有点慢
第 1000 次：500ms → 烦
```

**核心问题：** 用户每次都在为「不必要的事情」等待。

哪些等待是不必要的：

| 等待 | 次数/天 | 可消除？ |
|------|---------|---------|
| 项目检测 | 10 | ✅ 缓存命中直接跳过 |
| Backend 初始化 | 10 | ✅ 持久化连接池 / 热加载 |
| 工具注册 | 10 | ✅ 注册一次，序列化缓存 |
| Memory 加载 | 3-5 | ✅ 异步加载，不阻塞交互 |
| Workspace 准备 | 10 | ✅ 目录存在检查 < 1ms |

**目标：** 热启动从输入到可交互 < 50ms。冷启动 < 200ms。

**50ms 是什么概念？** 人的感知阈值 ≈ 100ms。50ms 的等待 = **用户感觉不到等待**。

### 2.5 切换摩擦

```
# 当前：需要退出 ZMAI 才能切换项目
zmai> exit
$ cd ../other-project
$ zmai

# 又需要等待启动、加载、检测...
```

**一年 3000 次中有 200-300 次是切换项目。**

每次切换 = 退出 + cd + 重新启动 + 重新检测 + 重新加载 Memory。

**解决方案：** ZMAI 应该支持在对话中切换工作目录。

```
zmai> cd ../other-project
  ↓
(自动: 保存当前 Memory → 新目录检测 → 加载新项目 Memory)
  ↓
zmai> 这个项目的架构是什么样的？
```

### 2.6 记忆摩擦

```
zmai> 上周五我在改哪个文件来着？
zmai> 我昨天做了哪些修改？
```

用户记不住上下文。**每次回忆都是摩擦。**

**解决方案：** Memory 自动记录并持久化。用户不需要回忆，直接说「继续」就行。

### 2.7 信任摩擦

```
zmai> 删除 node_modules
⚠ 确认执行 shell 命令吗？ [Y/n] Y      ← 第 500 次问同样的问题
```

**信任 = 不需要再说「请」的关系。**

```
第 1-5 次：确认                ← 学习期，需要确认
第 6-50 次：确认但可以 "不再询问"   ← 半信任期
第 51 次+：不再询问             ← 信任期
```

**解决方案：** 信任模式。默认严格，前几次确认后自动进入信任模式。

```
zmai> 删除 node_modules
(直接执行，不确认)
```

用户仍然可以随时关闭信任模式：

```
zmai> 进入安全模式
(之后所有操作都需确认)
```

### 2.8 输出噪音摩擦

每次执行完成后的输出：

```
✅ 完成
  read_file: src/main.py
  edit: src/main.py:45-50
  shell_exec: pytest tests/
```

第 1 次：清晰的步骤展示。
第 1000 次：**我可以只看结果吗？**

**解决方案：** 输出分级。

```
# 默认模式（日常使用）：
  ✅ 完成 (3 步, 12s)

# 详细模式（调试/复盘）：
zmai --verbose 或 zmai> 显示详情
  ✅ 完成
    read_file: src/main.py
    edit: src/main.py:45-50
    shell_exec: pytest tests/ (42 passed)

# 安静模式（管道/脚本）：
zmai -p "task" --json
  {"status": "completed"}
```

## 3. 重新设计

### 3.1 核心原则（长期版）

```
快                         → 每次等待都在消耗耐心
安静                       → 无消息 = 正常工作
记住                       → Memory 自动恢复
信任                       → 不需要重复确认
一致                       → 每次使用体验一致
可预测                     → 永远知道 Agent 下一步做什么
可打断                     → 随时可以修改指令
可恢复                     → 关闭后回来继续
```

### 3.2 启动体验（第 1 次 vs 第 3000 次）

**第 1 次启动：**

```
$ zmai
⚡ ZMAI · 首次启动
  检测到 ANTHROPIC_API_KEY
  Backend: Claude · claude-sonnet-4-6 (默认)

zmai> _
```

**第 3000 次启动：**

```
$ zmai
zmai> _
```

**差异：**
- 没有欢迎词
- 没有版本号
- 没有项目信息
- 没有 Backend 信息
- 没有 Memory 信息
- 没有 Agent 信息

**信息都在它们该在的地方：**
- 想看状态 → `zmai status`
- 出错了 → 自动显示错误
- 换项目了 → 自动检测并提示

### 3.3 执行体验

**第 1 次执行：**

```
zmai> 列出文件

  🔍 搜索文件列表...
  📂 read_dir(".") → 23 files
  ✅ 完成
```

**第 3000 次执行：**

```
zmai> 列出文件
  ✅ 23 files
```

**差异：**
- 没有步骤动画
- 没有工具调用细节
- 只有结果

**用户想看到步骤时：** `zmai --verbose 列出文件` 或 `zmai> 显示步骤`。

### 3.4 恢复体验

**第 1 次恢复：**

```
zmai -r

  📋 未完成任务:
  [1] 重构 auth 模块 · 昨天 17:30 · 进度 60%
  
  > 选择 (1):
```

**第 3000 次恢复：**

```
zmai                           ← 自动恢复最近未完成的任务
zmai> 继续
```

**差异：**
- 只有一个未完成任务时，自动恢复，不显示列表
- 用户不需要输入 `-r`，启动时自动检测
- 用户不需要选择，默认就是最近的任务

### 3.5 换项目体验

**第 1 次换项目：**

```
zmai> exit
$ cd ../other-project
$ zmai
```

**第 3000 次换项目：**

```
zmai> cd ../other-project
  ↓ (2ms → 检测到目录变化 → 保存当前 Memory → 加载新项目)
zmai> 这个项目是做什么的？
```

**差异：**
- 不需要退出
- 不需要重新启动
- Memory 自动切换

### 3.6 换 Backend 体验

**第 1 次换 Backend：**

```
zmai --backend deepseek 读文件
```

**第 3000 次换 Backend：**

```
zmai> 用 DeepSeek
zmai> 读文件
```

**差异：**
- 自然语言替代参数
- 不需要记 `--backend` 参数名
- 切换后永久生效（除非再换）

## 4. 输出规范

### 4.1 最终命令表

```
# 日常（99.5% 的使用）
zmai                      ← 自动恢复 + 交互模式
zmai "task"               ← 执行任务（位置参数）
zmai "task" --json        ← 执行任务 + JSON 输出

# 辅助（0.5% 的使用）
zmai status               ← 查看状态
zmai cancel               ← 取消任务
zmai --resume             ← 有多个未完成任务时选择
zmai --verbose "task"     ← 显示详细步骤
```

### 4.2 参数分级

```
看不见的参数（自动完成，用户不需要知道）:
  --backend                自动检测 + 缓存
  --agent                  自动映射
  --model                  自动选择
  --workspace              当前目录
  --no-color               NO_COLOR 环境变量

极少需要的参数（保留，但在帮助中不显示）:
  --verbose                显示详细步骤
  --json                   pipe 到文件时自动检测

常用的修饰参数（帮助中显示）:
  -p "task"                headless 模式（别名：位置参数也接受）
  -r                       恢复任务
  --resume                 恢复任务（长名）
```

### 4.3 输出分级

```
安静模式（默认）:
  zmai> read main.py
  ✅ 完成

详细模式:
  zmai --verbose read main.py
  📂 read_file("main.py") · 120 lines
  ✅ 完成 (0.3s)

调试模式:
  DEBUG=1 zmai read main.py
  [debug] 检测项目: my-project
  [debug] Backend: DeepSeek (缓存命中)
  [debug] Agent: swe (6 tools 已注册)
  📂 read_file("main.py") · 120 lines
  ✅ 完成 (0.3s · token: 423)

JSON 模式:
  zmai -p "read main.py" --json
  → {"status":"completed","steps":1,"output":""}
```

### 4.4 启动速度规格

```
场景              目标        测量方式
───────────────────────────────────────
热启动（缓存命中）  < 50ms     从 Enter → 出现 zmai>_
温启动（部分缓存）  < 150ms    从 Enter → 出现 zmai>_
冷启动（无缓存）    < 500ms    从 Enter → 出现 zmai>_
首次启动（配置）    < 5s       从 Enter → 配置完成
```

### 4.5 长期舒适度检查清单

```
快:
  [x] 热启动 < 50ms（感觉不到等待）
  [x] 所有操作 < 100ms（感觉不到延迟）
  [x] 后台预热（用户打字时完成初始化）

安静:
  [x] 启动无声（无消息 = 正常）
  [x] 执行简洁（默认只显示结果）
  [x] 信息分级（用户控制显示多少）

记住:
  [x] 自动恢复最近任务
  [x] 自动切换项目上下文
  [x] 永久保存 Memory
  [x] 记住用户偏好（Backend、信任模式、主题）

信任:
  [x] 默认信任模式（第 6 次起不再确认）
  [x] 一键切换安全模式
  [x] 可撤销操作（Ctrl+C 保留进度）

一致:
  [x] 每次启动体验相同
  [x] 输出格式稳定
  [x] 错误信息可预测

可预测:
  [x] 知道 Agent 下一步做什么
  [x] 工具调用前显示预览
  [x] 进度可见（但不喧宾夺主）

可打断:
  [x] 随时输入新指令
  [x] 随时 Ctrl+C（保留进度）
  [x] 随时修改上一步指令
```

## 5. 与 CLI_UX_DESIGN.md 的关系

CLI_UX_DESIGN.md 是「**第一天**应该怎么设计」。

LONG_TERM_CLI_DESIGN.md 是「**每一天**应该怎么体验」。

| 维度 | CLI_UX_DESIGN.md | LONG_TERM_CLI_DESIGN.md |
|------|-----------------|------------------------|
| 视角 | 产品经理 | 重度用户（3000 次/年） |
| 目标 | 容易上手 | 长期舒服 |
| 关键指标 | 学习时间 | 摩擦系数 |
| 设计重点 | 引导、帮助、展示 | 速度、安静、记忆 |
| 输出原则 | 简单 | 越来越少 |

**最终结论：**

> 一个好的 CLI，在第 1 天和第 3000 天，应该是同一个样子。
> 
> 区别在于：
> - 第 1 天，用户能看到 CLI 提供了什么。
> - 第 3000 天，用户专注于任务本身，CLI 是透明的。
>
> ZMAI 的目标不是让第 3000 天和第 1 天一样。
> ZMAI 的目标是让第 3000 天比第 1 天更轻松。
> 
> 因为每一天，ZMAI 都在学习用户。每一天，用户都在少做一些事情。
